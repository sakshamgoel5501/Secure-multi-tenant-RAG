## 1. Seed the users

This only needs Postgres, not the server. It creates the `accounts` table if it doesn't exist.

```bash
rag seed-users --password 'demo-password-1234'
```

The password needs at least 12 characters, and every demo account shares it. It creates 22 accounts, with the password changes not forced:

| Username | Role |
|---|---|
| `platform` | Platform administrator |
| `t1-admin`, `t2-admin`, `t3-admin` | Tenant administrators |
| `t1-eng`, `t1-hr`, `t1-fin` (same for `t2-`, `t3-`) | Users |
| `t1-eng-admin`, `t1-hr-admin`, `t1-fin-admin` (same for `t2-`, `t3-`) | Group administrators |

Running it again skips existing accounts, so it never overwrites a password someone changed. Because `platform` now exists, you don't need the `RAG_BOOTSTRAP_ADMIN_*` variables.

## If something fails

- **"RAG_ADMIN=1 needs RAG_ADMIN_KEY of at least 32 characters":** the key is too short.
- **Sign-in says incorrect username or password:** check that you seeded, and that the server was started with `--jwt`. Five wrong tries lock that account for 15 minutes.
- **"Storage folder ./qdrant_data is already accessed":** another server is still running. Stop it first.
- **The sidebar shows no pages for an account:** its role doesn't have access to them. Platform admins have no tenant pages by design.
